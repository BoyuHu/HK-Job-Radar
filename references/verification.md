# 有效性验证规则（最高优先级）

> 原则：**宁可少写，不可写入过期/不可验证的岗位。**

## 1. 三合一验证（每条候选必做）

写入前用 WebFetch 访问岗位链接，一次完成三件事：

1. **确认仍在线**：页面显示招聘中。出现 `expired` / `no longer advertised` / `closed` / 已下架 / 跳转到列表页 → 不写入。
2. **抓取 JD 全文**：职责 + 要求 + 薪资（如有）+ 雇佣类型。抓不到完整 JD（需登录/反爬/404）= 未验证，不写入。
3. **提取发布日期**：
   - 优先级：页面明确日期 > 相对时间倒推（"3 days ago" → 今天减 3 天）> 留空
   - **读不到就留空，绝不编造**
   - 搜索摘要与详情页的发布时间冲突时，以详情页为准

## 2. 时效规则

- 发布日期距运行日超过 `freshness_days`（profile 配置，默认 92 天）→ 不写入。
- **截止日期（closing date）已过 → 不写入**，即使发布时间显示很新（聚合站常见旧岗重发）。
- 无截止日期的岗位正常评估，但备注注明"无截止日"。

## 3. 写入与更新

- 通过验证的岗位写入时，备注统一加前缀：`[推荐]` 或 `[谨慎-原因]`，并注明 `已验证在线(截止日期X)`。
- JD 文案写入专用字段，上限 10000 字符，超长截断加 `...[truncated]`。
- 巡检发现表内既有记录已下线 → 该记录状态改为「过期」，备注加前缀 `[过期-岗位已下架]`，然后补抓新岗位凑满当日配额。

## 4. 失败处理

| 情况 | 处理 |
|---|---|
| 反爬黑名单域名 | 默认不写入，不浪费验证次数 |
| WebFetch 失败/需登录/404 | 视为未验证，不写入 |
| 单次搜索预算用完仍未满额 | 写入已验证数量，运行日志标注「待补足 N 条 / 已试源清单」，下次运行继续补 |
| 同一岗位多个链接变体 | 只保留一个（优先公司官网直链），其余视为重复 |
